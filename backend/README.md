# VerifiNews Backend

## Requirements

- Python 3.10 or newer (uses modern type-hint syntax)

## Setup

1. Create virtual environment:
   ```
   python -m venv venv
   source venv/bin/activate      # Windows: venv\Scripts\activate
   ```

2. Install dependencies:
   ```
   pip install -r requirements.txt
   ```

3. Copy `.env.example` to `.env` and fill in real values:
   ```
   cp .env.example .env
   ```
   - `DATABASE_URL`: get this from your Neon.tech project dashboard (Connection string)
   - `SECRET_KEY`: generate one with `python -c "import secrets; print(secrets.token_hex(32))"`

4. Run the server:
   ```
   uvicorn app.main:app --reload
   ```

5. Open API docs (auto-generated by FastAPI) at:
   ```
   http://localhost:8000/docs
   ```

## What's included so far

- `POST /auth/signup` — creates a user, returns JWT + user info
- `POST /auth/login` — verifies credentials, returns JWT + user info
- `POST /detect` — analyzes text or a URL, returns label + confidence, saves to history (requires login)
- `GET /history` — returns the logged-in user's past checks, paginated (requires login)
- `GET /users/me` / `PATCH /users/me` — view/update name, change password (requires login)
- `POST /report` — flag a detection result as wrong, one report per user per detection (requires login)
- `GET /admin/stats` — totals, fake/real ratio, last-7-days daily trend, pending reports count (admin only)
- `GET /admin/users` / `PATCH /admin/users/{id}` — list users, change role/status (admin only)
- `GET /admin/logs` — every detection ever run, filterable by `result_label` (admin only)
- `GET /admin/reports` / `PATCH /admin/reports/{id}` — list and review flagged results (admin only)
- Tables auto-created on startup: `users`, `detection_history`, `reports`

## Setting up HuggingFace (needed before /detect will work)

1. Create a free account at huggingface.co, go to Settings → Access Tokens, generate a token
   with "Read" access. Put it in `.env` as `HF_API_TOKEN`.
2. Search the HF Hub for a fake-news classification model (search "fake news detection" under
   Models, filter by Text Classification). Pick one with reasonable download/like counts.
3. Set `HF_MODEL_URL` in `.env` to:
   `https://api-inference.huggingface.co/models/<the-model-name-you-picked>`
4. **Important:** the first request to a model that hasn't been called recently can take 20-30
   seconds while HF "wakes it up" (cold start) — this is normal, not a bug. Subsequent calls
   are fast.
5. Different models return different label names (`FAKE`/`REAL`, `LABEL_0`/`LABEL_1`,
   `true`/`false`, etc). Call `/detect` once with a test article, check the raw label your
   model actually returns, and adjust the `fake_labels` set in
   `app/services/detection_service.py` (`_normalize_result` function) to match.

## Testing /detect

```bash
curl -X POST http://localhost:8000/detect \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <paste-your-token-here>" \
  -d '{"input": "Some news article text here...", "type": "text"}'
```

## Testing signup/login

Use the `/docs` Swagger UI directly, or curl:

```bash
curl -X POST http://localhost:8000/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"name":"Eman","email":"eman@example.com","password":"test1234"}'
```

Copy the `access_token` from the response — that's what the frontend will store and send as
`Authorization: Bearer <token>` on every protected request.

## Making the first admin

There's no signup path for admins yet (by design — see the security note in the system plan).
For now, manually update a user's role directly in the DB after they sign up normally:

```sql
UPDATE users SET role = 'admin' WHERE email = 'your-admin-email@example.com';
```

(You can do this from the Neon.tech SQL editor in your browser — no extra tool needed.)
